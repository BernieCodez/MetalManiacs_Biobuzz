Not sure how? Read below.

### Naming Conventions
Folders & Packages - Use flatcase. Ex "teleop"  
Classes - Use PascalCase. Ex "ExampleAuto"  
Methods & Variables - Use camelCase. Ex "toggleIntake"  
Constants - Use UPPER_SNAKE_CASE. Ex "MAX_SPEED"

### Project Architecture
teleop - code that is controlled by a human  
auto - code that is NOT controlled by a human  
pedro - pedro pathing related stuff (edit constants when updating new tuned values)  

### Version History
Before pushing changes, make sure to name your push the 
correct thing!  
To do so, open Github Desktop, in the top left, right 
under the MetalManiacs_Biobuzz repository (make sure you
are in the right one) there should be a "History" tap.
Clicking it will open the version history. Find the top
most push and increment the version number in your push
summary.  
Our versioning system goes like this: v_._._
The first _ is the competition number we are preparing 
for.  
The second _ is the major update. This includes creating
new files or significant changes to existing files.  
The third _ is the minor/bug fix update. This includes
editing a few lines in certain files or readjustment
of variable values.

### AI Policy
Generally, try to avoid using AI when coding, since it
takes out all the fun in coding. Challenge yourself
and only when ABSOLUTELY NECESSARY should you turn to AI.  

Remember: AI is a tool, so treat it as such. Don't let it
replace you, but allow it to help you when you are stuck.  

Acceptable levels of AI usage:
 - Explaining what code does
 - Brainstorming solutions
 - Debugging dumb stuff

Gray area:
Writing lines of code. It's acceptable as long as
you completely understand what it is doing and can 
thoroughly explain it to another software member.

I (Bernie) would like to keep this year's repository as 
clean as possible, so try not to just let an AI agent run 
free in the repo pls 🙏
